# Worlds — the recordable demo scenarios

One dashboard, seven loadable worlds. A world is a **scenario preset** (`world/scenarios/*.json`):
a reset + seed of the same world engine, not a second engine on another port. Loading a
world clears the world DB and reapplies its clock, cast, friends, edges, beliefs, outfits,
items, scene art and ending card. Switch room history is not cleared, so use a distinct
room per take if the transport transcript matters.

| id | Title | Cast | Clock | What it proves |
| --- | --- | --- | --- | --- |
| `w1-gift` | The Gift | all four | 18:20 | The user arrives with an object; Alice is the first to know; the gift becomes a belief. |
| `w2-two-clocks` | Two Clocks | all four | 17:40 | Mock time jumps to the café; `REAL xN` runs the same beat against the wall clock. |

| `w4-three-of-us` | Three of Us | Alice, Emily, Mia | 20:00 | A three-person scene where the connection graph, not cast order, picks the speaker. |
| `w5-good` | Three Ways — Good | all four | 21:30 | The same setup as the bad end, but the ledger supports **GOOD END — The Confession**. |
| `w5-bad` | Three Ways — Bad | all four | 21:30 | The good setup with a colder ledger supports **BAD END — The Leak**. |
| `w6-long-tuesday` | The Long Tuesday | all four | 08:00 | The original five-beat arc and the remove-Switch fallback. |

## Takes

Each world has a matching take in `world/takes/<id>.json`: 2 scenes, a scene art plate,
opening/choices, deterministic cues, polished fallback lines, a `next` pointer and a
`must_change` gate. Load a take from the **Takes** shelf or:

```sh
curl -X POST http://127.0.0.1:8890/api/takes/w3-quiet-route/load \
  -H 'Content-Type: application/json' -d '{}'
curl -X POST http://127.0.0.1:8890/api/takes/next \
  -H 'Content-Type: application/json' -d '{}'   # 409 until a turn/cue changed something
```

The w3 causal chain is explicit: default cardigan → user preference cue → belief → next
scene outfit change. The fallback lines are authored/polished, marked `authored` when a
live speaker misses the deadline.

## Load

Dashboard → **Worlds** → **Load & play**, or:

```sh
curl -X POST http://127.0.0.1:8890/api/scenarios/w3-quiet-route/load \
  -H 'Content-Type: application/json' -d '{}'
```

`GET /api/scenarios` lists them; `GET /api/scenarios/current` shows the active one;
`POST /api/endings/evaluate` returns the scenario's ending card and evidence.

## What the scenario carries

- `clock` (`now`, `mode`, `scale`), `cast` (present set), `friends`, `absent`
- `relationships` and `beliefs` (upserted into the normal ledger)
- `outfits` per character (id, label, art, reason, source belief)
- `cast_art`, `scene_art`, `scene_art_evening` (the `w2` day/evening A/B)
- `item` (a single chip for the demo; no inventory economy)
- `opening` (title, line, choices) and `ending` (card + evidence)

`GET /api/state` exposes `scenario`, `outfits`, `cast_art`, `scene_art`, `item`,
`connections` and the usual ledger. `connections` is a cast↔cast projection of the
directed relationship rows (`close`, `steady`, `strained`, `rival`, `distant`); the World
Tree has a lens for it.

## Recording notes

- One active world at a time. Load is a reset, not a merge.
- `w2` switches the art at 17:00; the `REAL xN` badge is honest about a compressed clock.
- `w3`'s outfit is a **memory → outfit → date** chain, not a costume shop: the belief
  (`user-prefers-short-skirt`) is the source, and the outfit card shows it.
- `w5-good` / `w5-bad` are pre-seeded forks. Load the good world, record; load the bad
  world, record the same cue. Do not replay the whole story to fork.
- `w6` is the fallback if a new scenario fails validation; it keeps the original arc.

## Art

The demo plates live in `web/assets/scenes/` and `web/assets/portraits/outfits/`; the
manifest is `world/demo-assets.json`, generated by `scripts/generate-demo-assets.py`.
The script downloads each render, writes the web JPEG, and deletes the studio library
entry (`DELETE /api/v1/library/image/<name>`) after verifying it is gone.
